# Mathematical typography research and proposed plan

Research date: 2026-10-29. Sources and local artifact hashes are in [sources.json](sources.json). Source claims below are observations, not adopted numerical acceptance thresholds. The captured Unicode revision 15 is stable but old; the live revision 16 is a proposed update, not a final replacement. Public access is not a blanket republication license. The STIX project files are useful provenance, not a rendered specimen; the Unicode PDF contains actual character illustrations.

## Boundary and transfer

The Sublimite state-of-design note, rubric, council document and review JSON concern editor interfaces: physical size, rendering, screenshot discipline, pairwise review and human judgment. Their UI criteria, exemplar applications, model choices, costs and project-specific gates are not evidence about math font shapes and are not binding here. Transfer only the ideas of controlled comparison, visible evidence, explicit disagreements and a human decision; design the math-specific fixtures and scoring afresh. The archived project is historical, not an active protocol.

## Proposed implementation plan, not a council run

1. Define target engines, text companion, repertoire, script sizes, devices and license-compatible comparison fonts. Record versions and hashes; acquire approved specimens and pin licenses. M05 identifies STIX distribution and its text/math family; this is not proof that any particular STIX version matches an arbitrary prose face.
2. Create a curated, versioned fixture corpus covering the table above, inline and display equations, nested structures, Greek pairs, alphabets and long prose. Document expected semantic distinctions and expected engine behavior, with separate reference output for each engine. Include low-resolution and print-scale views, native size and enlarged crops; record renderer, resolution, font and settings.
3. Establish mechanical checks for cmap/repertoire, parseable MATH data, required glyph constructions, mappings and reproducible rendering. A valid table alone does not establish visual quality; missing optional features are not automatically violations. Classify failures as font, engine, fixture or unknown.
4. Draft a rubric for recognizability, spacing and rhythm, scripts and accents, scalable constructions, and coherence with prose. Each observation must cite a fixture and location. Propose 1/3/5 anchors as severe interference / usable with visible issues / consistently clear and coherent; calibrate with real examples before adopting any thresholds. No numeric distance, size, score or improvement threshold is supported by these sources.
5. Pilot blind pairwise reviews on identical render settings, including an identical-pair control and independent written reasons. Reveal identities only after scoring; preserve disagreement and inspect actual-size pages. Decide acceptance and stopping rules only after measuring reviewer consistency and obtaining the project owner's preferences. Do not conflate a screenshot winner with engineering conformance or accessibility evidence.

## Limits

No actual fonts, generated specimens, implementation or council execution were produced. The captured Unicode report is informative, not a conformance standard; coverage must be tied to the project's chosen Unicode version and use cases. The Microsoft specification is necessary engineering evidence but does not prescribe a complete typesetting algorithm or aesthetic quality. The STIX historical account is not specifically evidence of every STIX Two design decision. No controlled legibility study or quantitative minimum sizes were established. M08's attribution and §7 have been verified against the official issue; reproduction rights for individual TUGboat articles remain unverified, so only links and short paraphrases are retained. Further first-party STIX Two design documentation and licensed specimen fonts should be acquired before choosing references.
